01. Core Concepts at a Glance

🔄

The Event Loop

A single-threaded scheduler that manages coroutines in a ready queue, polling non-blocking I/O events and dispatching ready tasks.

⚡

Tasks vs Coroutines

Calling an async function returns an unstarted coroutine. Wrapping it in asyncio.create_task() schedules it immediately for background concurrency.

⏸️

Cooperative Yielding

When a task executes await on an I/O operation, it suspends execution and yields control back to the event loop so other ready tasks can run.

🧵

Offloading Blocking Work

Never block the loop with time.sleep(). Use asyncio.to_thread for blocking I/O and ProcessPoolExecutor for CPU-heavy tasks.

Direct Await EX 02

Awaiting Coroutines Directly

Shows why awaiting raw coroutines one after another executes sequentially without concurrency, despite running inside an event loop. 

async def main():
    result1 = await fetch_data(1)
    result2 = await fetch_data(2)
    return [result1, result2]

Concurrent Tasks EX 03

Scheduling with create_task

True concurrency! By wrapping coroutines with asyncio.create_task(), both tasks run in parallel in the background while the event loop manages them. 

async def main():
    task1 = asyncio.create_task(fetch_data(1))
    task2 = asyncio.create_task(fetch_data(2))
    return [await task1, await task2]

Order Independence EX 04

Awaiting in Different Orders

Awaiting Task 2 (2s) before Task 1 (1s). Shows that Task 1 completes in the background regardless of when its result is awaited. 

async def main():
    task1 = asyncio.create_task(fetch_data(1))
    task2 = asyncio.create_task(fetch_data(2))
    r2 = await task2  # Await task 2 first!
    r1 = await task1  # Already complete!

Critical Gotcha EX 05

Blocking the Event Loop

The fatal mistake: using synchronous time.sleep() inside a coroutine freezes the entire thread, halting all other concurrent tasks. 

async def fetch_data(param):
    time.sleep(param)  # ⛔ Freezes event loop!
    return f"Result of {param}"
